## Правила работы (от владельца репозитория)

- **Не коммитить и не пушить.** Это делает только владелец. Остальной git (status, diff и т.п.) можно;
  изменения оставлять неиндексированными — владелец сам решает, что коммитить.
  Репозиторий: https://github.com/Nepike/knt-wiki (публичный). Сервер забирает код оттуда (`git pull`),
  поэтому перед деплоем изменений владелец должен закоммитить и запушить.
- **sudo на сервере выполняет владелец сам** (у `nepike` sudo с паролем). Готовить для него точные команды.
- Безвозвратное удаление данных (rm -rf и т.п.) не выполнять самому — давать команду владельцу.
- Работаем по этапам; после каждого этапа остановиться, показать результат, ждать подтверждения.
- На сервере: команды, которые удаляют, перезаписывают или перезапускают существующие сервисы, —
  только после явного «да» владельца.
- В статьях не выдумывать факты об отделе: спрашивать или ставить заметную пометку TODO.
- Никаких паролей/токенов/ключей в статьях — только у кого/где их получить.
- Перед правкой существующей статьи сначала скачать её текущую версию из вики (могли править в браузере).
- Статьи публикуются сразу в боевую вики, только после одобрения владельца.

## Как деплоить

Подробно — README. Коротко: владелец пушит → на сервере `cd /srv/knt-wiki && bash scripts/deploy.sh`.
Просто `git pull` НЕ применяет LocalSettings.php: файл смонтирован по одному (single-file bind mount), pull
создаёт новый inode, контейнер видит старый до `docker compose restart mediawiki` — deploy.sh это делает.
Каталог `assets/` смонтирован целиком, он обновляется сразу. Конфиг nginx (`deploy/nginx/`) копирует владелец через sudo.
Перед обновлением версии MediaWiki — `bash scripts/backup.sh`.

## Как публиковать статьи

`.venv/Scripts/python scripts/wiki.py check|status|pull|diff|publish` (подробно — README, «Статьи»).
- Бот-пароль в локальном `.env`: `WIKI_URL`, `WIKI_BOT_USER`, `WIKI_BOT_PASSWORD` (гранты: editpage,
  createeditmovepage, editinterface). Переменные окружения `WIKI_*` перекрывают `.env` — так тестировать на
  локальной вики: `WIKI_URL=http://localhost:8080` + локальный бот-пароль
  (`docker compose exec mediawiki php maintenance/run.php createBotPassword --appid publisher --grants basic,editpage,createeditmovepage,editinterface Admin <32+ символа>`).
- Файл → страница: `articles/<Название>.wiki`, `articles/<Пространство>/<Название>.wiki`.
- `articles/.sync.json` — база ревизий по каждому адресу вики; publish отказывает при изменении в вики после pull.
  После локальных тестов удалять из него секцию localhost.
- **Никогда не делать `pull` из локальной вики в `articles/`** — это перезаписывает черновики для прода
  (случилось 2026-09-27, черновик восстановлен). Теперь pull отказывает на несинхронизированных черновиках,
  а `--force` сохраняет старую версию в `*.wiki.bak`. Проверять разметку черновика — через API `parse`
  локальной вики (ничего не сохраняет), а не через publish/pull.
- Публиковать ТОЛЬКО после одобрения владельца (publish всегда показывает diff; `--yes` — только после одобрения).
- Шаблоны: `Шаблон:Статус страницы` (ответственный, проверено=ГГГГ-ММ-ДД; >180 дней — предупреждение;
  без параметров — категории «Страницы без ответственного/даты проверки»), `Шаблон:TODO` (категория
  «Страницы с TODO»). Оба с TemplateData. Проверены на локальной вики.

## Заметки для тестов

- Запросы к `http://127.0.0.1:8080` с заголовком `X-Forwarded-Proto: https` получают Secure-cookie,
  и логин через API по http не проходит — это нормально, в тестах этот заголовок не передавать.
- Тестовые прогоны install/backup/restore делать в копии репозитория в scratchpad с другим `name:` в compose
  и портом 8081, потом `docker compose down -v` в этой копии.

## Особенности окружения (Windows владельца)

- Git Bash: при передаче путей вида `/tmp` в docker нужен `MSYS_NO_PATHCONV=1`.
- Python в консоли: `PYTHONIOENCODING=utf-8`, иначе падает на кириллице.
- curl в Git Bash портит кириллицу в аргументах — для API с русскими заголовками использовать Python.
- `core.autocrlf=true`, поэтому в репозитории `.gitattributes` с `eol=lf`. Python `write_text` на Windows
  пишет CRLF — передавать `newline="\n"`.
